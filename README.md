# 知析台（Xueshu）

一个面向材料化学与人工智能论文工作的本地研究工作台。它完全独立实现，不连接学术坊服务，也不注册任何自定义 URL 协议；
唯一的外部 AI 请求发往你在设置页填写的 OpenAI 兼容接口。

包含两个工作面：

- **材料研究工作台** —— 区分论文、专利、实验记录、数据集和研究题目，逐篇分析并生成带证据门禁的综合报告
- **科研协作工作台** —— 材料数据员 / AI 建模员 / 论文证据员并行工作，各自调用 skill 并归档产物

## 快速开始

双击 `启动网站.cmd`。

首次运行会自动完成：创建 Python 虚拟环境 → 安装后端依赖 → 安装并构建前端 → 启动本地服务并打开浏览器。
之后每次启动只需要几秒。服务地址固定为 <http://127.0.0.1:8765>。

> 前置条件：本机已安装 **Python 3.11+** 和 **Node.js 18+**（首次构建前端需要 Node）。
> 脚本会自动绕过 PowerShell 执行策略，无需手动改系统设置。

首次使用请先到「接口设置」填写 Base URL、模型名称和 API Key，然后点「测试连接」。

## 文献工作台

1. 「材料研究」→ 新建项目，填写研究问题、研究类型、材料体系与目标期刊。
2. 选择来源类型后上传 PDF / DOCX / TXT / Markdown，可一次选择多篇。
3. 点「开始分析」，页面实时显示六阶段进度与事件日志。
4. 完成后在线预览报告，并下载 Markdown / JSON / DOCX。

六阶段任务：排队 → 解析准备 → 逐篇分析 → 跨文献综合 → 生成导出 → 完成。

### 抽取的是什么：证据原子，不是摘要

每篇按 18000 字符分块，每块抽成结构化的**证据原子**：

| 字段 | 内容 |
| --- | --- |
| `findings` | `{claim, conditions, quote}` —— 论断 + **成立范围** + 支撑原句 |
| `equations` | `{latex, meaning, symbols, conditions, quote}` —— 公式以 LaTeX 为准，必须带符号表与适用条件 |
| `evidence` | `{quote, page}` —— 逐条回原文核对 |

**为什么条件必须留**：没有适用范围的结论无法安全复用。`claim` 说"掺杂提高了容量保持率"，
`conditions` 说"2.8–4.3 V、25 °C、0.5C 倍率下循环 200 周"——有了后者，这条论断才能被精确引用而不是含糊转述。

**引文核对**：把模型给的短引**去掉所有空白后**回原文做子串匹配。PDF 抽出来的正文换行位置不可靠，
不归一化会把正确引用误判成「待核对」。核对是**论断级**的：每条论断用它自己的引文，
不是整段里随便一条引文顶包。

### 综合：先去重聚类，再写

几十篇文献里真正不同的论断往往只有十几个，其余是重复表述。所以综合之前先做一次**论断聚类**：

```
逐篇抽取 → 摊平成带编号的证据原子 → 聚类去重（同一件事归一组）
        → 只把「论断簇」喂给综合环节 → 输出主题 / 共识 / 分歧 / 空白
```

喂进综合环节的是聚类结果而不是全部原始分析，输入小一个数量级，模型才不会在长上下文里丢细节。
论断少于 12 条时跳过聚类（不值得多花一次调用）；**聚类失败或模型漏掉论断时，漏掉的自动补成单例簇**
——宁可粒度粗，也不能丢论断。

报告里会列出聚类结果：每个主题几条论断、来自几个来源。

### 质量门禁

报告开头就是门禁状态。只有**证据完整性**问题才让它翻红：

- 有来源属于「研究题目/方案」，不能当研究发现证据
- 有论断缺少可核对的原文短引

缺少适用条件、公式缺符号表属于质量提醒，计入计数但**不翻红**——否则几乎每次都会亮红，用户很快就学会无视它。

> ⚠️ `conditions` 是靠模型填的字段。实测模型会把它写成"补充说明"或"原因"而不是真正的适用范围，
> 这时计数仍显示"0 条未写明"。**计数只能告诉你字段是否留空，告诉不了你内容是否写对。**
> 提示词里已经明确禁止"复述结论、解释原因"，但这一项最终仍需要人工看一眼。

**来源类型要选对**：一道竞赛题/研究方案如果被当成「研究论文」上传，门禁的第一道防线就失效了
——它的陈述会被当作研究发现。上传时按实际情况选，或在项目里改。

### 长文档的韧性与断点续跑

一篇 24 页的文献会被切成 6 块，每块的模型调用要 2–3 分钟。为了不让「慢」变成「失败」：

| 机制 | 说明 |
| --- | --- |
| **超时单独放宽** | 逐篇分析用 600 秒，聊天与连接测试仍是 180 秒。可用 `XUESHU_ANALYSIS_TIMEOUT` 覆盖 |
| **自动重试** | 超时 / 连接失败 / 限流 / 5xx 会指数退避重试（默认 3 次尝试，`XUESHU_ANALYSIS_ATTEMPTS` 可调）；鉴权、参数类错误不重试 |
| **断点续跑** | 每块分析完立即落库（`document_chunks` 表）。重新发起分析时，已完成的分块直接复用，只跑缺的部分，事件里会写「复用了 N 个已完成分块」 |
| **单块失败降级** | 一块跑不过去不再作废整篇：报告照常出，门禁里标明「N 个分块分析失败，报告内容不完整」 |

缓存的有效性由**内容哈希 + 提示词版本**共同决定：正文变了、或抽取提示词有实质改动
（`pipeline.PROMPT_VERSION` 递增），对应分块会自动重跑 —— 不会拿旧结果糊弄新提示词。

> 这四条是为修一个真实故障加的：一篇 90614 字符的文献切成 6 块，单块耗时在 **128–181 秒**之间
> 波动，而当时的超时线正好是 **180 秒**。结果是每次调用都贴着线跑，一块踩线就作废整篇，
> 而且重跑等于从头再来（6 块全部重算）。现在超时放宽 + 自动重试把失败率压下去，
> 断点续跑让真正失败时不白等，单块降级保证最坏情况下也还能拿到报告。

## 协作工作台

点侧边栏「科研协作」进入。三名成员同时推进，各自有职责、清单、进度与产物分类。

| 成员 | 角色 | 交付目标 |
| --- | --- | --- |
| 材料数据员 | Materials Data | 从原文逐页提取并核验 `evidence_table.csv`；有真实行级数据时才生成可追溯图表 |
| AI 建模员 | ML Researcher | 有逐样本特征与标签时建模；只有文献时提交 `modeling_limitations.md`，不制造指标 |
| 论文证据员 | Manuscript & Evidence | 维护论断—证据对应关系，生成结构完整且标明待核验内容的 `report.md` |

**三种进入方式**：

1. **从课题发起**（推荐）：在「材料研究」的课题详情页点右上角「发起科研协作」。
   会自动带上课题名称、研究类型、研究问题、材料体系、目标期刊，并把该课题**已解析的文献复制**进
   协作任务的 `input/` —— 不用在两边各传一次。建好后直接跳到协作页并选中这个新任务。
2. 点侧边栏「科研协作」，在「新建协作任务」里填名称与目标，再上传材料。
3. 已有协作任务时，页面顶部可以切换任务。

三个成员角色是**固定的**，不能选。你能决定的是任务名称、目标描述、上传什么材料。
工具栏里的「任务详情」「一键式工作流」是为版式预留的禁用占位，尚未实现。

输入材料支持 **PDF / DOCX / TXT / MD / CSV / TSV / JSON / XLSX**。
上传的数据文件会原样放到工作目录的 `input/` 下，AI 建模员可以直接用 `pandas.read_csv("input/xxx.csv")` 读取。

> `input_text` 仍封顶 12000 字符以控制首次提示长度，但原始文件会完整复制到 `input/`。
> 后端同时生成页数、页级字符数和 SHA-256 来源清单；成员可用 `read_document` 按页读取全文，
> 不再需要为了覆盖后续页面而重新上传或手工拆分。

### agent 是怎么工作的

每名成员是一个独立的对话循环，通过**自写的 skill 协议**调用工具（不依赖接口的 function calling 能力，
任何 OpenAI 兼容模型都能跑）：

```
模型输出： <skill name="run_python">{"code": "...", "filename": "chart.py"}</skill>
宿主执行： 在受限沙箱里跑，返回
回灌模型： <result name="run_python">退出码：0 … 新增文件：fig_trend.png</result>
……
模型输出： <finish>已交付 2 张趋势图</finish>
```

可用 skill：`list_files`、`read_file`、`read_document`、`write_file`、`run_python`、`finish`。

### 协作证据与建模门禁

- 文献型任务的材料数据员交付 `evidence_table.csv`，每行至少包含 `source_file`、`page`、`quote`、`claim`。
  宿主会把引句归一化后回到指定文件、指定页做子串核验；模拟页内容和错误页码不能通过。
- 图表是可选产物。只有真实逐样本数值且可解释时才作图；图片正文不会作为乱码进入模型上下文，
  论文证据员只读取相应 `.meta.json`。
- 只有 PDF/DOCX/TXT/MD 而没有 CSV/TSV/XLSX/Parquet 行级数据时，AI 建模员不能产出训练/测试指标，
  必须用 `modeling_limitations.md` 说明缺失的特征、标签、划分和验证条件。
- 论文证据员启动前，队长只汇入通过门禁的证据表、限制说明、结果表和图表元数据；脚本与图片二进制不会进入写作上下文。
- 协作模型调用单次上限 180 秒、最多 2 次；重试原因与等待时间会显示在协作终端，最坏等待约 6 分钟。
`write_file` 支持 `"mode": "append"`，在已有文件末尾追加内容，改长文档时用它。
三名成员共享同一个工作目录，所以论文证据员能直接读到材料数据员和 AI 建模员的产出。

成员结束后，队长做汇总：写一份 `队长汇总.md`，登记产物，并把任务置为完成。

### 运行中实时指令

每张成员卡片下方都是该成员独立的实时指令区，不是任务结束后的聊天回合：

- 成员正在调用模型时，指令先显示“等待注入”，并在**下一次模型调用前**加入同一段上下文。
- 论文证据员等尚未启动的成员也能接收指令；它会排队，并在该成员第一轮调用时生效。
- 指令被上下文取走后显示“已注入”；任务撤销前仍未取走的指令显示“未生效”。
- 如果指令恰好在模型回复 `<finish>` 时到达，宿主会撤回本次结束并继续任务，避免结束边界丢消息。
- 每批实时指令会为该成员增加 4 个执行步骤，累计最多增加 8 步，既给调整留出空间又避免无限运行。
- 已完成、失败或撤销的成员不再接受输入；接口返回 409，不会另起一个绕过门禁的事后修改线程。
- 指令记录会持久化，刷新页面后仍能看到它是否已经注入。

> **为什么 `write_file` 有追加模式**：实测让能力一般的模型「改一份长文档」时，它会卡在
> 反复读取上直到耗尽步数 —— 因为它得把全文重新吐成 JSON 字符串再写回去。
> 所以 `write_file` 支持 `"mode": "append"`，这时 `content` 只写新增的部分。
> 换成追加之后，同一个模型完成同样的修改从「275 秒仍未完成」变成「40 秒完成」。

### 版本历史与回退

**每个协作任务的 `work/` 目录就是一个独立 git 仓库**（内置 git，用本机已安装的 `git`）。

每次「修改完成」都会自动提交一次：

| 时刻 | 提交者 | 说明示例 |
| --- | --- | --- |
| 任务开始 | 队长 | `任务开始` |
| 某成员跑完一轮 | 该成员 | `材料数据员：已交付数据审计与图表` |
| 队长汇总后 | 队长 | `队长汇总` |
| 执行一次回退后 | 队长 | `回退到 a1b2c3d` |

左侧导航的「历史」页汇总所有任务的版本，支持按日期范围、关键词（任务名 / 说明 / 成员 / 文件名）
过滤，支持按时间正序倒序排列，显示每次提交改了哪些文件（`A` 新增 / `M` 修改 / `D` 删除）。
点「回到此版本」即可回退。

几个实现上的取舍：

- **回退不是 `reset --hard`**。它把工作区内容恢复成那个版本，然后**新建一次回退提交**，
  所以历史不会被抹掉，回退这个动作本身也可以再被回退。
- **`input/` 不进版本库**。回退要回退的是工作产出，不是用户上传的原始材料。
  同理 `.mplconfig/`、`__pycache__/` 这些运行时垃圾也被忽略。
- **提交发生在「静止点」**。skill 的实际执行与快照是串行的，提交也排在这条队列里，
  因此不会把别的成员写了一半的工作区当成一个版本记下来。
- 回退后会重建产物清单，归属尽量沿用回退前的记录，认不出来的算队长名下。
- 启用版本管理之前就存在的任务，服务启动时会补一个「启用版本管理前的快照」，
  这样历史页不会对老任务显示为空。

### 产物预览与就地编辑

产物面板里点一行就地展开预览，**不用先下载**：

| 类型 | 预览方式 |
| --- | --- |
| 图片（png / jpg / svg / webp …） | 直接出图，点击在新标签页看原图 |
| Markdown | 用报告预览同款渲染器排版 |
| CSV / TSV | 排成表格，最多前 50 行 × 前 8 列 |
| 代码 / 文本 | 等宽代码块 |
| docx / xlsx / pdf | 提示下载后查看 |

文本类产物右上角有「编辑」：改完保存会**直接写回文件并产生一个 git 版本**，
提交者记成「我」，和三名 agent 的改动在历史页上一眼区分得开。

两个保护：

- 内容超过 200 KB 时只给前一部分预览，**这时编辑会被禁用** —— 免得把截断的内容保存回去。
- 任务正在运行时不允许编辑（409），避免和 agent 抢同一个文件。

### 把产物发送到一个网址

产物预览右上角有「发送」：填一个接收地址，点发送，文件就以 `multipart/form-data`
直接 POST 过去，字段名默认是 `file`。

```
POST /api/collab/artifacts/{artifact_id}/send
body: { "url": "https://example.com/upload", "field": "file" }
→ { "ok": true, "status": 200, "url": "...", "filename": "fig_trend.png",
    "size": 24255, "response": "对端响应前 500 字" }
```

- 只接受 `http` / `https`；地址里带账号密码会被拒绝（400）。
- 沿用项目的域名边界：学术坊域名会被拒（400）。
- 单文件上限 50 MB，超时 60 秒，**不跟随跳转**。
- 对端返回非 2xx 时接口返回 **502** 并带上对端响应片段，不会谎报成功。
- 每次发送都会在协作终端留一条记录。

### 与真实模型的兼容性

协议是自写的，但解析器刻意写得宽容，因为实测不同模型输出差别很大：

- 标准写法 `<skill name="list_files">{}</skill>` 当然支持；
- 有些模型（实测 `qwen`）会把工具名直接当标签：`<list_files> {} </list_files>`，同样能解析；
- `list_files` 这类不需要参数的工具，模型在里面乱填「无」之类的非 JSON 内容也不会报错；
- 参数写成非法 JSON 时不会直接失败，而是把错误回灌给模型让它重写。

三名成员的工具集是**按角色收敛**的：材料数据员和 AI 建模员有 `run_python`，论文证据员只有
`list_files` / `read_file` / `write_file`。这是实测逼出来的 —— 给弱模型执行能力，
它会跑去干别人的活（论文成员自己去画图，结果既不写报告又和其他成员抢文件名）。
越权调用会被明确拒绝，并告诉它该用什么。

即便如此，**模型能力仍然是这里最脆弱的一环**。实测 `qwen` 级别的小模型偶尔会连续
几步填错参数，把 8 步上限耗光。这时成员会明确失败，任务不会伪装成已完成。
如果反复出现，建议换一个更强的模型，或把任务目标写得更具体一点。

注意：材料数据员缺少图表、AI 建模员缺少脚本或结果数据、论文证据员缺少 `report.md` 时，
完成门禁会把该成员和整项任务标为**失败**，避免界面在关键产物缺失时误报完成。

### 执行沙箱的边界（请认真读）

模型生成的 Python 会被真正执行，所以做了这些限制：

- **超时**：单次执行上限 60 秒，超时后连同子进程树一起结束（`taskkill /T /F`）。
- **禁网**：通过 `PYTHONPATH` 注入 `sitecustomize.py`，在解释器层面拦截对外连接与域名解析。
- **独立目录**：以任务自己的工作目录为 cwd，只继承最小环境变量，**不传递任何 API Key**。
- **路径约束**：所有文件读写都必须落在工作目录内，`../` 越界会被拒绝。

但要说清楚：**这不是真正的安全沙箱**。禁网只作用于 Python 层面的网络调用，
生成的代码如果去启动 `curl`、`git` 之类的子进程，那道出口不受约束；它也没有做文件系统与权限隔离。
把它当成"防手滑"而不是"防恶意"，不要拿它跑来源不明的题目。

另外，为了产出归属准确（避免 A 把 B 刚写出的文件记成自己的），**skill 的实际执行是全局串行的**；
模型调用仍然完全并发，所以界面上三名成员依然是同时在推进的。

## 网络边界

- 后端只监听 `127.0.0.1`，不对局域网或公网开放。
- 硬性禁止配置 `xueshufang.com` 及其子域名，`llm_client.validate_base_url()` 会直接拒绝。
- 出站请求只发往用户填写的接口，不会访问其他服务。
- API Key 不写入日志，接口不回显密钥原文，也不会传进协作沙箱的子进程环境。
- 不包含会员、余额、充值、支付、远端账号或自定义协议处理。

## 已知限制

- 扫描型 PDF 无法提取文字，会被标记为「解析失败」并提示先做 OCR，本工具不内置 OCR。
- 文献分析按 18000 字符分块，超长文献会多次调用模型，耗时与费用随之增加。
  逐篇分析的耗时**主要花在模型生成输出上**，一次调用两三分钟是常态；分块越小越快，
  但分块越多总调用次数越多。`document_parser.chunks_from_pages` 的 `max_chars` 可调。
- `conditions` 靠模型填，实测模型会把它写成"补充说明"或"原因"而不是适用范围，
  这时门禁计数仍显示"0 条未写明"。**计数只能判断字段是否留空，判断不了内容是否写对。**
- 协作任务的 `input_text` 封顶 12000 字符，但成员可以使用 `read_document` 按页读取 `input/` 中的完整文献。
- PDF 里公式的文本抽取本就不可靠：正文里没有公式痕迹时，`equations` 为空是正常结果，
  未必是解析器丢了东西 —— 需要打开原文核对。
- 文献分析并发上限为 2，同一项目同时只允许一个任务；协作任务的 skill 执行全局串行（见上）。
- 服务重启时未完成的任务会被标记为中断，需要重新发起，协作工作目录里的产物会保留。
- 协作页成员卡片上的勾选清单来自宿主确定性质量门禁，不按执行步数假装完成。
- 协作任务里模型能力是最脆弱的一环：小模型可能连续几步填错参数而耗尽步数上限，
  单个必需成员失败会让整项任务未通过完成门禁，但其他已生成产物仍会保留供排查。
- 三名成员共享同一个工作目录。为了产物归属准确，skill 的实际执行是全局串行的
  （模型调用仍并发）；同名文件会被后写入的覆盖。
- 实时指令只在协作运行期间开放，并在成员结束收口时原子关闭，避免“已结束但仍误接收”的竞态。
- 历史页会把所有任务的 `git log` 都读一遍再在内存里过滤，任务数量很多时会变慢。
- 回退只影响工作产出，`input/` 里的上传材料不会被回退。
- 回退是「恢复内容 + 新增一次回退提交」，不会丢失历史，但也意味着回退之后
  再想回到「回退前」需要找到对应版本再回退一次。
- 重新开始协作任务会清空该任务的工作目录（保留 `input/` 里的输入材料）。

## 维护提醒

`scripts/` 下的两个 `.ps1` 必须保存为 **UTF-8 带 BOM**。这台机器上只有 Windows PowerShell 5.1，
它读取没有 BOM 的 UTF-8 脚本时会按系统 ANSI 代码页解析，脚本里的中文提示会变成乱码。
用编辑器改完这两个文件后，记得确认 BOM 还在。
